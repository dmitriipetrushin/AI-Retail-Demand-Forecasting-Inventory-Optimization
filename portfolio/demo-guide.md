# Two-minute recruiter demonstration

Presenter: **Dmitry Petrushin — Independent Project Owner — AI Implementation & Project Management**. The retailer and stakeholder roles are fictional; the sales records are historical UCI data. Start with `streamlit run app.py`, then use the sidebar **Workspace** radio buttons. All expected numbers below originate from the saved real-data experiment or the stated simulated budget.

| Time | Exact UI action | What to show / say |
|---|---|---|
| 0:00–0:20 | Open **Executive Dashboard** | “Retail managers balance stockouts, excess inventory and limited purchasing funds. I built a local decision-support study for 25 products, with human control over recommendations.” Point out the observed metric labels versus modeled inventory/cost labels. |
| 0:20–0:45 | Select **Demand Forecasting**; leave first product `85123A`; keep **28** days and **Final holdout** | Show the actual daily-sales line, AutoETS and seasonal naive. “I selected products before validation, used three historical rolling origins and froze the selected model before the final 28 days. Holdout WAPE is 70.5%; improvement does not eliminate large errors.” Select **Future refit** briefly to show post-history forecasts with no actuals. |
| 0:45–1:10 | Select **Inventory Recommendations** | Show assumed stock, on-order, lead days and safety stock in the editable grid, then the rounded recommendation table. “Inventory and supplier inputs are assumptions. The target covers lead plus review time, then applies safety stock, MOQ and packs.” Increase a current-inventory cell and click **Apply assumptions** if time allows; the corresponding order should fall or remain unchanged at a pack boundary. |
| 1:10–1:30 | Select **Budget Optimization**; click **Run budget optimization** with £3,000; change **Purchasing budget (£ per review)** to £1,500 and press Enter, then click **Run budget optimization** | Show OPTIMAL, allocation/spare budget and FIFO comparison. The earlier plan becomes invalid when the budget changes. Click **Accept simulated plan**; the app explicitly confirms that no purchase was submitted. A zero budget produces a valid zero-order plan. |
| 1:30–1:50 | Select **Business Impact**; use **base**, then **tight_budget** | “A better forecast did not guarantee lower inventory cost: base Strategy B cost 1.30% more and C cost 2.36% more than A. Optimization improved modeled cost by 3.35% in the tight-budget scenario. These are scenario outputs, not verified savings.” Point to poor fill rates and the sensitivity chart. |
| 1:50–2:00 | Select **Evaluation & Deployment Readiness** | “GO for a tested local demonstration; conditional analytical shadow pilot with real operational inputs; NO-GO for production procurement.” Show the frozen protocol, model comparison and known risks. |

If demonstrating precise screenshots, restart a fresh browser session so inventory edits do not carry over. The default post-history inventory value differs from the holdout simulation's initial stock because it uses a later history prefix; they are explicitly separate contexts. Live budget edits affect the proposed plan, not the fixed simulation evidence.
